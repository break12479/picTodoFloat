# **PicTodo Float —— 产品需求文档（PRD）**

> **文档版本**：3.1（3.0 据当前实现回填；3.1 为界面打磨：统一图标、任务 ⋯ 菜单、标题栏工具，见第六节）
> **产品名称**：PicTodo Float
> **目标平台**：Windows 10 / 11（桌面端）
> **核心定位**：一款轻量级、高性能、始终悬浮于桌面的个人任务管理工具。**以文字任务为核心载体，支持像 PixPin 一样顺滑地为任务添加图片（截图/粘贴/拖拽即入），并可为复杂任务关联一份本地 Markdown 文档做深度沉淀**，具备 PixPin 所缺失的可编辑文本、数据持久化与分类整合能力。

> **三层内容模型**：每条待办由「标题层（文本，支持 Markdown 渲染，快速一览）+ 视觉层（图片附件）+ 深度层（关联的 .md 文档）」组成。列表始终紧凑，复杂度按需溢出到外部文档/弹层，兼顾轻量与深度。

> **相对 2.1 版的主要变更**（开发过程中依实际体验调整，详见各节）：
> - 图片「查看全部图片」不再是内嵌画廊式预览窗，而是每张图各自打开一个独立的 PixPin 式悬浮小窗（见 3.3）。
> - 便签模式放弃了原计划的实时 Markdown 预览编辑器（CodeMirror 方案与搜狗输入法在 WebView2 下有丢字冲突，见 3.2）。
> - 新增：归档（3.8）、搜索（3.7）、多选批量操作（3.6）、分组拖拽排序、深色/浅色主题、数据存储位置自定义与迁移。
> - 任务文本改为 Markdown 渲染（GFM），并新增字符数截断 + 展开全文弹层。

------

## 一、产品概述

用户在处理创意、设计、写作、学习等任务时，常需将文字任务与视觉素材（如参考图、截图、手稿）关联。

**产品灵感来源于 PixPin**：PixPin 是一款优秀的截图工具，可将截图悬浮于桌面任意位置。但它存在两个硬伤：

1. **图片无法配可编辑的文本，且没有持久化**——只能保存图片本身，无法作为可管理的待办；
2. **缺乏整合能力**——无法积累、无法分类。

**PicTodo Float 要做的**：保留 PixPin「截图即悬浮」般顺滑的图片添加、查看体验，但把它变成一个**以文字为核心、图片为增强**的悬浮待办工具。文字任务是主体（支持 Markdown），图片是可选的视觉附件；所有内容持久化保存，支持排序、分组、归档、搜索、批量整理，实现「所见即所管、可积累、可分类、可检索」。

------

## 二、目标用户

- 设计师、插画师、内容创作者
- 学生（整理笔记 + 配图）
- 项目经理（附带原型图 / 截图的任务）
- 普通用户（记录带图的购物清单、旅行计划等）

## 三、核心功能需求

### 3.1 基础悬浮体验

| 功能           | 说明                             |
| ------------ | ------------------------------ |
| **始终置顶**     | 窗口不被其他应用遮挡                     |
| **无边框透明窗口**  | 背景半透明（可调节，见下）                  |
| **主题**       | 深色 / 浅色两套主题，设置中一键切换，持久化保存       |
| **面板不透明度**   | 设置中滑块调节 50%~100%，持久化保存         |
| **自由拖拽**     | 鼠标拖动标题栏移动整个面板                  |
| **窗口位置/尺寸持久化** | 记住上次窗口位置与大小，重启后恢复（由 window-state 插件负责，非应用自身数据表） |
| **最小化到托盘**   | 关闭按钮隐藏窗口到托盘；托盘图标右键菜单「显示/退出」，左键双击显示 |
| **开机自启（可选）** | 设置中开关，状态持久化并实际生效               |
| **全局快捷键**    | `Ctrl+H` 显隐主窗口（未聚焦时也生效）        |

### 3.2 任务管理

| 功能        | 说明                       |
| --------- | ------------------------ |
| **新建任务**  | 底部紧凑输入框：`Enter` 提交，`Shift+Enter` 换行，自动增高（最高 140px）；输入框左侧可选目标分组（默认「默认组」） |
| **便签模式（新增）** | 点击 ⤢ 展开为全屏浮层，遮住整排底部工具；`Enter` 换行、`Ctrl+Enter`（或 `⌘+Enter`）保存为任务、也有显式「✓ 保存」按钮、`Esc` 或 × 收起（收起不丢草稿）。用普通 `<textarea>` 实现，**不做实时 Markdown 预览**——早期用 CodeMirror 做过 Obsidian 式实时预览，但搜狗输入法快速连按空格确认候选词时会丢字，排查过 5 个方向（装饰重建时机、回声抑制、去自定义装饰插件、拦截空格 keydown 等）未解决，判断是 WebView2 + 搜狗 + CodeMirror 更底层的交互问题，故改回普通 textarea |
| **编辑任务**  | 在任务文本区域 400ms 内连续点击两次进入编辑模式（不依赖浏览器原生 `dblclick`，因其在 WebView2 下行为不稳定，改为手动计时判定） |
| **Markdown 渲染** | 任务文本按 Markdown（GFM，含删除线、任务列表等；单个换行按 `<br>` 处理）解析为 HTML 显示，经 DOMPurify 消毒后渲染（`marked` + `dompurify`） |
| **长文本折叠**  | 任务原文超过 180 字符时，列表内按字符数截断预览并显示「展开全文」按钮；点击后弹出模态框渲染完整 Markdown，框内可直接进入编辑 |
| **标记完成**  | 勾选复选框，完成后文字显示删除线 + 灰色，并按分组规则沉底（见 3.4.2） |
| **删除任务**  | 任务 ⋯ 菜单（或右键）中的「删除」，二次确认弹窗后移除（含关联图片；确认框支持 `Enter` 确认、`Esc` 取消）；批量删除见 3.6 |
| **任务操作菜单（3.1）** | 行尾 ⋯ 按钮（悬停/选中时显示）点击，或在任务上右键，弹出菜单：置顶/取消置顶、归档、移动到（列出默认组与全部分组，当前所在组打勾）、删除。替代原先悬停时在行内展开的按钮条——那种做法展开时会挤压文字导致重排 |
| **数据持久化** | 所有任务、图片、排序、分组、归档状态自动保存至本地，重启不丢失 |

### 3.3 图片支持（PixPin 式体验）

> ✅ **图片是任务的增强附件，一条任务可关联 0~N 张本地图片；文字仍为任务主体**

| 功能         | 详细说明                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| **添加图片**   | **① 剪贴板粘贴**：`Ctrl+V` 把截图软件复制的图贴入当前**已选中**的任务（需先点选一条任务，否则提示先选中）；**② 拖拽本地图片文件** 直接拖到某条任务上 |
| **图片格式**   | 由粘贴/拖入的浏览器 `image/*` MIME 类型决定，常见 `.jpg/.jpeg/.png/.bmp/.webp` 均可                    |
| **缩略图展示**  | - 默认显示前 3 张缩略图（40×40px，取后端生成的独立缩略图文件 `thumb_path`，非原图缩放）- 超过 3 张时第 3 张叠加显示「+N」- 鼠标悬停缩略图右上角出现「×」，点击直接删除该图（无需进入预览） |
| **查看大图（与 2.1 版不同）** | 点击任意缩略图 → **打开一个独立的无边框、置顶、透明背景悬浮小窗**（每次点击新开一个，类似 PixPin 悬浮截图），只显示这一张图，**不提供跨图导航**（无左右箭头/画廊/索引，每图各自开窗、各自关闭） |
| **悬浮小窗交互** | - 拖动图片 = 系统级拖动整个窗口，跟手、可跨屏 - 鼠标滚轮 = 实际缩放窗口尺寸（`setSize`，非 CSS transform），范围 0.2×~5× - `Ctrl+C` 复制图片到系统剪贴板（右下角短暂提示「已复制」）- `Esc` 或双击关闭 - 窗口禁用系统 resizable/maximizable，避免拖到屏幕边缘触发 Windows Snap 贴边 |
| **删除单张图片** | 缩略图行内悬停即可删除（见上），不再需要先进入预览层                                                          |
| **图片存储方式** | 采用**文件路径存储**：原图与生成的缩略图分别复制/生成到应用数据目录下，数据库仅存相对路径（`file_path`/`thumb_path`）与元数据（原名、大小、排序）。数据目录本身可迁移，见 3.9 与五、非功能性需求 |

### 3.4 任务排序与分组

> 重要程度：**手动拖拽排序 > 分组 > 置顶**。

#### 3.4.1 手动拖拽排序

| 功能         | 说明                                                        |
| ---------- | --------------------------------------------------------- |
| **拖拽排序**   | 用户可上下拖动任意任务改变顺序，顺序（`sort_order`）持久化保存；跨分组拖拽会同时改变所属分组。**无独立拖拽手柄：鼠标按住任务行任意位置移动超过 5px 即开始拖动；触摸屏上长按约 250ms 再拖动，快速划动仍是滚动列表**（单击、双击、右键不受影响；行尾 📄 / ⋯ 按钮、行内编辑框、展开全文弹层内不触发拖动）。因此非编辑状态下不能用鼠标拖选任务文字，需要复制文字时可进入编辑或打开「展开全文」 |
| **默认尊重手动序** | 除非用户主动点击「自动排序」，否则始终保持用户拖拽的顺序，不自动重排                        |
| **自动排序按钮** | 标题栏排序图标（全局）或组标题悬停出现的排序图标（组内）：未完成任务在上、已完成任务沉到底部（全局按钮作用于所有组，组内按钮只重排该组）；已完成任务之间按完成时间排序，最近完成的在上 |
| **多选整体拖拽（新增）** | 见 3.6：多选状态下拖动其中一项，选中的所有项（置顶项除外）按展示顺序整体移动             |

#### 3.4.2 分组（手动分组优先于按状态自动分组）

| 功能           | 说明                                                            |
| ------------ | ------------------------------------------------------------- |
| **手动分组**     | 用户可创建分组，将任务归入某分组；未归组的任务进入「默认组」                                 |
| **分组本身可拖拽排序（新增）** | 按住分组标题栏拖动即可调整分组显示顺序（鼠标在标题栏上显示为抓手，触摸屏为长按后拖动；标题栏右侧的排序/删除按钮、重命名输入框内不触发）；置顶区/默认组固定位置，不参与                    |
| **分组可折叠/重命名** | 组标题左侧箭头折叠整组；双击组名可重命名                                          |
| **新建/删除分组** | 列表末尾「+ 新建分组」，点击变为输入框，`Enter` 确认、`Esc` 取消；组标题悬停出现删除图标，组内有任务时先二次确认（任务移到默认组，不会被删除） |
| **分组内独立排序**  | 每个分组内部独立排序：该组的已完成任务沉到**本组底部**，最近完成的在上                       |
| **完成后留在原组**  | 任务被标记完成后，仍留在其所属分组，只是沉到该组底部——手动分组归属优先于按状态自动分组                  |
| **已完成任务折叠（新增）** | 设置项「折叠已完成任务」（默认开启）：开启时每组已完成任务合并为一行「已完成 (N)」按钮，点击展开/收起；该设置为全局开关，同时作用于所有分组；**置顶分区不受此设置影响，永远整体可见** |
| **默认组空则自动隐藏（新增）** | 「默认组」在没有任务时不渲染，不占面板空间                                         |
| **按状态自动分组**  | 在未做手动分组时，按「未完成 / 已完成」两个自然区块展示，已完成区块置于底部（同「已完成折叠」逻辑）             |

#### 3.4.3 置顶任务

| 功能       | 说明                                        |
| -------- | ----------------------------------------- |
| **置顶任务** | 置顶的任务永远显示在列表最顶部独立分区，不受分组和完成状态影响；仅能在置顶分区内部拖拽重排，不支持跨组拖拽把任务拖入/拖出置顶——置顶/取消置顶只能通过任务 ⋯ 菜单（或右键）中的「置顶 / 取消置顶」 |

### 3.5 关联文档（文档沉淀）

> ✅ **深度层**：当一条任务内容变复杂时，可关联一份本地 Markdown 文档做资料汇总与沉淀。文本仍是待办主体，md 文档是按需展开的深度内容。

| 功能         | 详细说明                                                                 |
| ---------- | -------------------------------------------------------------------- |
| **功能总开关（新增）** | 设置中「启用关联文档功能」勾选项：关闭后仅隐藏任务上的 📄 入口，**不影响已有的文档关联**（数据不丢失，重新开启即恢复显示） |
| **文档标记**   | 已关联文档的任务常显一个高亮的 📄 图标，点击直接用系统默认程序打开；未关联的任务仅在悬停时显示该图标（减少列表噪音），点击弹出菜单可「关联已有 .md / 新建文档」 |
| **关联已有文档** | 点击 → 弹出文件选择器（`tauri-plugin-dialog`，过滤 `.md/.markdown`）→ 选择本地文件 → 存储绝对路径（适配用户已有的 Obsidian / Typora 笔记） |
| **新建文档**   | 点击 → 在**用户配置的笔记文件夹**下生成 `.md` 文件，预填任务标题为 H1 → 存储相对笔记文件夹的路径 → 打开        |
| **打开方式**   | **外部打开**：通过 `tauri-plugin-opener` 调用系统默认 `.md` 程序（Typora / Obsidian / VS Code），不内置编辑器 |
| **快速取消关联（新增）** | 长按 📄 图标 550ms 直接取消关联（无需先打开菜单）                                       |
| **笔记文件夹**  | 用户可在设置中配置笔记根目录，默认 `文档/PicTodoFloat Notes`；可指向 Obsidian 仓库或 OneDrive / 坚果云等同步目录 |
| **断链处理**   | 每次任务加载时校验文档路径是否存在；不存在时图标显示红色 `!` 角标，点击弹出菜单可「重新关联」或「移除关联」，**绝不静默丢失引用** |
| **存储方式**   | 任务侧仅存文档路径（`doc_path`）：应用新建的笔记存相对笔记文件夹的路径，用户关联的外部文件存绝对路径             |

> 💡 应用内 md 预览/编辑仍未实现，保持外部打开。

### 3.6 多选与批量操作（新增）

| 功能         | 说明                                                        |
| ---------- | --------------------------------------------------------- |
| **单选**     | 点击任务文本区域外的空白（任务行本身）选中该任务，作为粘贴图片（3.3）与拖拽的目标/锚点             |
| **范围多选**   | `Shift+点击` 以上一次选中项为锚点，按**当前展示顺序**（可跨分组）选中区间内所有任务          |
| **追加/取消多选** | `Ctrl/Cmd+点击` 将某任务加入或移出已选集合                                |
| **批量工具条**  | 选中 ≥2 项时，列表顶部出现「已选 N 项」工具条：**归档**（一键批量）/ **删除**（二次确认后批量删除）/ **取消选择** |
| **多选整体拖拽** | 拖动已选中项中的任意一项，会把全部选中项（不含置顶项）按展示顺序整体移动到拖拽目标分组与位置                |

### 3.7 搜索（新增）

| 功能         | 说明                                                        |
| ---------- | --------------------------------------------------------- |
| **入口**     | 标题栏搜索图标（搜索栏打开时高亮），或快捷键 `Ctrl+F`；搜索栏固定在列表上方，不随列表滚动 |
| **匹配方式**   | 对任务文本做不区分大小写的子串匹配，实时过滤                                     |
| **范围限定**   | 搜索栏内下拉可选「全部 / 置顶 / 某个分组 / 默认组」，仅在该容器内匹配                  |
| **搜索态限制**  | 搜索结果非空时，过滤后为空的分组自动隐藏；搜索激活期间禁用拖拽排序（`DndContext` sensors 置空） |
| **空结果提示**  | 无匹配任务时显示「没有匹配的任务」                                          |
| **关闭**     | 点击 × 或 `Esc` 关闭搜索栏并清空查询词/范围                                |

------

### 3.8 归档（新增）

| 功能         | 说明                                                        |
| ---------- | --------------------------------------------------------- |
| **手动归档**   | 任务 ⋯ 菜单（或右键）中的「归档」，单条归档；或多选后在批量工具条点「归档」                        |
| **归档面板**   | 标题栏归档图标打开（`Esc` 关闭），列出全部已归档任务（文本 + 归档日期），每条可「取消归档」（恢复到原分组与列表）或「删除」（二次确认，彻底删除，含级联删除关联图片） |
| **自动归档（可配置）** | 设置中「完成后自动归档」下拉：关闭 / 3 天 / 7 天 / 14 天 / 30 天；已完成任务超过所选天数后，应用在下次拉取任务列表时自动将其移入归档 |
| **归档任务的可见性** | 归档后的任务不出现在主列表、不参与分组统计、拖拽排序、多选，仅在归档面板中可见                    |

### 3.9 用户体验细节

| 场景           | 行为                              |
| ------------ | ------------------------------- |
| **空任务状态**    | 主列表为空（无任务也无分组）时显示「还没有任务」及快捷键提示（`Ctrl+N` 聚焦输入、选中任务后 `Ctrl+V` 贴图） |
| **错误提示**     | 操作失败或提示类信息（如未选中任务就粘贴图片）以提示条显示在输入栏上方，约 4 秒后自动消失，也可点 × 关闭 |
| **长文本裁切**   | 预览除按 180 字符截断外，还检测是否被最大高度裁掉（中文一行字少，常常不到 180 字就超高）；两种情况都显示底部渐隐 +「展开全文」 |
| **无图片任务**    | 不显示任何图片区域，节省空间                  |
| **高 DPI 屏幕** | 自动适配 125%、150%、200% 缩放          |
| **快捷键**      | `Ctrl+N`：聚焦新建任务输入框；`Ctrl+H`：隐藏/显示主窗口（全局）；`Ctrl+F`：打开搜索；`Ctrl+V`：向选中任务粘贴图片 |
| **数据位置迁移**   | 设置中可将数据存储位置（数据库 + 图片）切换到任意本地文件夹（便于放入坚果云/OneDrive 同步目录），切换时旧数据保留原地作为备份，绝不删除；见五、非功能性需求 |
| **性能要求**     | 启动时间 <1s；50 条任务（每条平均 2 张图、单张 ≤500KB）时内存占用 ≤80MB、列表滚动 ≥60fps |

## 五、非功能性需求

| 类别       | 要求                                        |
| -------- | ----------------------------------------- |
| **安全性**  | 不联网、不收集用户数据、所有内容仅存于本地                     |
| **兼容性**  | Windows 10 20H2 及以上，x64 架构                |
| **数据存储** | 任务/分组/设置/归档状态存 SQLite；图片与缩略图存数据目录下 `images/`，数据库存相对路径；md 笔记存用户配置的笔记文件夹（默认 `文档/PicTodoFloat Notes`） |
| **数据位置可迁移** | 默认数据目录为 `AppData`，用户可在设置中改到任意本地文件夹（含云同步目录）；切换时通过 SQLite `VACUUM INTO` 复制数据库、复制 `images/` 目录到新位置，旧位置数据原样保留作备份；应用数据目录下的指针文件记录当前生效路径，重启后自动沿用 |
| **更新机制** | 初期无自动更新，后续可扩展「检查更新」菜单项                    |
| **多语言**  | 首版仅中文，无需多语言                              |

## 六、界面原型示意（文字描述）

```
[ PicTodo Float ]                     🔍 ⇅ 🗄 ⚙ │ — ×   ← 标题栏：搜索/全部自动排序/归档/设置
┌──────────────────────────────────────────┐
│ ⌄ 📌 置顶 (1)                               │ ← 置顶分区，永远在最顶
│   ○  紧急：修复线上 Bug                       │
│                                            │
│ ⌄ 设计 (4)                            ⇅ 🗑 │ ← 组操作悬停才出现；按住标题栏可拖动分组
│   ○  完成项目封面设计                   📄 ⋯ │ ← 📄=已关联 md 文档（常显）；⋯ 悬停出现
│      [🖼️][🖼️][+2]                          │ ← 缩略图与文字左对齐
│   › 已完成 2                                │ ← 已完成折叠为一行，点击展开
│                                            │
│ ⌄ 购物 (2)                                  │
│   ○  购买生日礼物（附参考图）                   │
│      [🖼️][🖼️][🖼️]                         │
│ + 新建分组                                   │
│                                            │
│ ╭[默认组 ⌄] 添加任务…               ⤢ [+]╮ │ ← 一体化输入栏
└──────────────────────────────────────────┘
```

> **点击任意 [🖼️] → 各自打开一个独立的悬浮小窗只显示这张图**（非内嵌画廊，无索引/无左右切换）；拖动窗口=移动，滚轮=缩放，`Ctrl+C`=复制，`Esc`/双击=关闭。
> **点击 📄 → 用系统默认程序打开关联的 md 文档；无文档时点击弹出菜单可新建/关联；长按可直接取消关联**。
> **点击 ⋯ 或右键任务 → 置顶 / 归档 / 移动到分组 / 删除**。
> **按住任务行拖动可改变顺序/分组（无独立手柄，左侧不留手柄栏）；点击「自动排序」才按规则重排；按住分组标题栏可拖动调整分组顺序**。
> **`Shift`/`Ctrl` 点击任务可多选，列表上方出现批量工具条**。
> **点击搜索图标或 `Ctrl+F` 弹出搜索栏，可限定搜索范围**。
> **点击 ⤢ 展开为便签全屏输入，`Ctrl+Enter` 保存**。
> **图标统一为单色线性 SVG（跟随主题文字色），不使用彩色 emoji**；上图中的 emoji 仅为文字示意。
