# **PicTodo Float —— 产品需求文档（PRD）**

> **文档版本**：2.1
> **产品名称**：PicTodo Float
> **目标平台**：Windows 10 / 11（桌面端）
> **核心定位**：一款轻量级、高性能、始终悬浮于桌面的个人任务管理工具。**以文字任务为核心载体，支持像 PixPin 一样顺滑地为任务添加图片（截图/粘贴/拖拽即入），并可为复杂任务关联一份本地 Markdown 文档做深度沉淀**，具备 PixPin 所缺失的可编辑文本、数据持久化与分类整合能力。

> **三层内容模型**：每条待办由「标题层（文本，快速一览）+ 视觉层（图片附件）+ 深度层（关联的 .md 文档）」组成。列表始终紧凑，复杂度按需溢出到外部文档，兼顾轻量与深度。

------

## 一、产品概述

用户在处理创意、设计、写作、学习等任务时，常需将文字任务与视觉素材（如参考图、截图、手稿）关联。

**产品灵感来源于 PixPin**：PixPin 是一款优秀的截图工具，可将截图悬浮于桌面任意位置。但它存在两个硬伤：

1. **图片无法配可编辑的文本，且没有持久化**——只能保存图片本身，无法作为可管理的待办；
2. **缺乏整合能力**——无法积累、无法分类。

**PicTodo Float 要做的**：保留 PixPin「截图即悬浮」般顺滑的图片添加体验，但把它变成一个**以文字为核心、图片为增强**的悬浮待办工具。文字任务是主体，图片是可选的视觉附件；所有内容持久化保存，支持排序、分组、分类整合，实现「所见即所管、可积累、可分类」。

------

## 二、目标用户

- 设计师、插画师、内容创作者
- 学生（整理笔记 + 配图）
- 项目经理（附带原型图 / 截图的任务）
- 普通用户（记录带图的购物清单、旅行计划等）

## 三、核心功能需求

### 3.1 基础悬浮体验

| 功能           | 说明                             |
| ------------ | ------------------------------ |
| **始终置顶**     | 窗口不被其他应用遮挡                     |
| **无边框透明窗口**  | 背景半透明（默认 85% 不透明），可调节          |
| **自由拖拽**     | 鼠标拖动任意位置移动整个面板                 |
| **窗口位置持久化**  | 记住上次窗口位置，重启后恢复到原位置             |
| **窗口尺寸持久化**  | 记住上次窗口大小，重启后恢复到原尺寸             |
| **最小化到托盘**   | 关闭按钮隐藏窗口，右键系统托盘图标可恢复或退出        |
| **开机自启（可选）** | 用户可在设置中开启，**设置状态持久化保存并实际生效**   |

------

### 3.2 任务管理

| 功能        | 说明                       |
| --------- | ------------------------ |
| **新建任务**  | 输入文本后按 Enter 或点击「+」添加    |
| **编辑任务**  | 双击任务文本进入编辑模式             |
| **标记完成**  | 勾选复选框，完成后文字显示删除线 + 灰色    |
| **删除任务**  | 每项右侧「×」按钮，确认后移除（含关联图片）   |
| **数据持久化** | 所有任务、图片、排序、分组自动保存至本地，重启不丢失 |

------

### 3.3 图片支持（PixPin 式体验）

> ✅ **图片是任务的增强附件，一条任务可关联 0~N 张本地图片；文字仍为任务主体**

| 功能         | 详细说明                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| **添加图片**   | 核心要求：体验对标 PixPin。支持 **① 剪贴板粘贴**（`Ctrl+V` 直接把截图软件复制的图贴入任务）、**② 拖拽本地图片文件** 到任务上。 |
| **图片格式**   | `.jpg`, `.jpeg`, `.png`, `.bmp`, `.webp`                                          |
| **缩略图展示**  | - 默认显示前 3 张缩略图（尺寸：40×40px）- 超过 3 张时，第 3 张显示为「+N」叠加图标 - 缩略图横向排列于任务文本右侧            |
| **查看全部图片** | 点击任意缩略图 → 弹出**图片预览窗口**                                                            |
| **预览窗口功能** | - 显示当前任务**所有关联图片** - 支持左右箭头切换 / 鼠标滚轮翻页 - 支持缩放（Ctrl+滚轮）和拖动查看大图 - 按 `Esc` 或点击关闭按钮退出 |
| **删除单张图片** | 预览窗口中每张图右上角显示「×」，点击可移除该图（不影响其他图片）                                                 |
| **图片存储方式** | ⚠️ **修订**：采用**文件路径存储**——图片复制到应用数据目录（`AppData`），数据库仅存相对路径与元数据（原名、尺寸、排序）。避免 Base64 撑爆数据库、拖垮性能与内存。 |

------

### 3.4 任务排序与分组（核心新增）

> 重要程度：**手动拖拽排序 > 分组 > 置顶**。三项均纳入 **V1.0**。

#### 3.4.1 手动拖拽排序（最高优先级）

| 功能         | 说明                                                        |
| ---------- | --------------------------------------------------------- |
| **拖拽排序**   | 用户可上下拖动任意任务改变顺序，顺序（`sort_order`）持久化保存                     |
| **默认尊重手动序** | 除非用户主动点击「自动排序」，否则始终保持用户拖拽的顺序，不自动重排                        |
| **自动排序按钮** | 点击后按规则重排：未完成任务在上、已完成任务沉到底部；已完成任务之间**按完成时间排序，最近完成的在上**     |

#### 3.4.2 分组（手动分组优先于按状态自动分组）

| 功能           | 说明                                                            |
| ------------ | ------------------------------------------------------------- |
| **手动分组**     | 用户可创建分组（如 A 组、B 组），将任务归入某分组；未归组的任务进入「默认组」                   |
| **分组内独立排序**  | 每个分组内部独立排序：该组的已完成任务沉到**本组底部**，最近完成的在上                       |
| **完成后留在原组**  | 任务被标记完成后，仍留在其所属分组，只是沉到该组底部——**手动分组归属优先于按状态自动分组**           |
| **按状态自动分组**  | 在未做手动分组时，按「未完成 / 已完成」两个自然区块展示，已完成区块置于底部                     |

#### 3.4.3 置顶任务

| 功能       | 说明                                        |
| -------- | ----------------------------------------- |
| **置顶任务** | 置顶的任务永远显示在列表最顶部，不受分组和完成状态影响；可取消置顶恢复正常排序    |

------

### 3.5 关联文档（文档沉淀）

> ✅ **深度层**：当一条任务内容变复杂时，可关联一份本地 Markdown 文档做资料汇总与沉淀。文本仍是待办主体，md 文档是按需展开的深度内容。

| 功能         | 详细说明                                                                 |
| ---------- | -------------------------------------------------------------------- |
| **文档标记**   | 每条任务显示一个 📄 图标按钮：无文档时点击可「关联/新建」，已有文档时图标高亮，点击直接打开                    |
| **关联已有文档** | 点击 → 弹出文件选择器（`tauri-plugin-dialog`）→ 选择本地 `.md` → 存储路径（适配用户已有的 Obsidian / Typora 笔记） |
| **新建文档**   | 点击 → 在**用户配置的笔记文件夹**下生成 `.md` 文件，预填任务标题为 H1 → 存储路径 → 打开                |
| **打开方式**   | **外部打开**：通过 `tauri-plugin-opener` 调用系统默认 `.md` 程序（Typora / Obsidian / VS Code），不内置编辑器 |
| **笔记文件夹**  | 用户可在设置中配置笔记根目录，默认 `文档/PicTodoFloat Notes`；可指向 Obsidian 仓库或 OneDrive / 坚果云等同步目录，实现可移植与被现有工具接管 |
| **断链处理**   | 加载时校验路径是否存在；文件被移动/删除时显示「断链」角标，提供「重新关联」，**绝不静默丢失引用**                 |
| **存储方式**   | 任务侧仅存文档路径（`doc_path`）：应用新建的笔记存相对笔记文件夹的路径，用户关联的外部文件存绝对路径             |

> 💡 V1 采用外部打开；应用内 md 预览/编辑作为 V2 可选增强。

------

### 3.6 用户体验细节

| 场景           | 行为                              |
| ------------ | ------------------------------- |
| **空任务状态**    | 显示提示：「点击『+』添加第一条任务」            |
| **无图片任务**    | 不显示任何图片区域，节省空间                  |
| **高 DPI 屏幕** | 自动适配 125%、150%、200% 缩放          |
| **快捷键**      | `Ctrl+N`：新建任务；`Ctrl+H`：隐藏/显示窗口；`Ctrl+V`：向选中任务粘贴图片 |
| **性能要求**     | 启动时间 <1s；50 条任务（每条平均 2 张图、单张 ≤500KB）时内存占用 ≤80MB、列表滚动 ≥60fps |

## 四、数据模型（实现约束）

> 供开发参考，与 3.3 / 3.4 的存储与排序需求对齐。

**Task**

| 字段          | 说明                              |
| ----------- | ------------------------------- |
| `id`        | 主键                             |
| `content`   | 任务文本（核心载体，可为空但图片任务建议有备注）        |
| `completed` | 是否完成                           |
| `completed_at` | 完成时间戳（用于已完成区按时间排序）           |
| `sort_order`| 手动拖拽顺序                        |
| `group_id`  | 所属分组（可空 = 默认组）                 |
| `pinned`    | 是否置顶                           |
| `doc_path`  | 关联的 md 文档路径（可空；新建笔记存相对路径，外部关联存绝对路径） |
| `created_at` / `updated_at` | 时间戳                |

**TaskImage**

| 字段          | 说明                              |
| ----------- | ------------------------------- |
| `id`        | 主键                             |
| `task_id`   | 所属任务                           |
| `file_path` | 相对应用数据目录的图片路径（**非 Base64**）    |
| `original_name` / `file_size` | 元数据             |
| `sort_order`| 图片在任务内的排序                     |

**Group**（新增）

| 字段          | 说明                              |
| ----------- | ------------------------------- |
| `id`        | 主键                             |
| `name`      | 分组名称（如 A、B）                    |
| `sort_order`| 分组显示顺序                        |

**AppSettings**（新增，持久化）：窗口位置 `x/y`、窗口尺寸 `width/height`、窗口透明度 `opacity`、开机自启 `auto_start`、笔记文件夹路径 `notes_folder`（默认 `文档/PicTodoFloat Notes`）。

## 五、非功能性需求

| 类别       | 要求                                        |
| -------- | ----------------------------------------- |
| **安全性**  | 不联网、不收集用户数据、所有内容仅存于本地                     |
| **兼容性**  | Windows 10 20H2 及以上，x64 架构                |
| **安装方式** | 单文件 .exe，无需安装，绿色运行                        |
| **数据存储** | 任务/分组/设置存 SQLite；图片文件存 `AppData` 目录，数据库存相对路径；md 笔记存用户配置的笔记文件夹（默认 `文档/PicTodoFloat Notes`） |
| **更新机制** | 初期无自动更新，后续可扩展「检查更新」菜单项                    |
| **多语言**  | 首版仅中文，无需多语言                              |

## 六、界面原型示意（文字描述）

```
[ PicTodo Float - 悬浮面板 ]
┌──────────────────────────────────────┐
│ 📌 紧急：修复线上 Bug                  │ ← 置顶任务，永远在最顶
│                                      │
│ ▼ A 组：设计                          │ ← 手动分组
│   □  完成项目封面设计            📄   │ ← 📄=已关联 md 文档
│      [🖼️][🖼️][+1]                   │ ← 3 张图，第 3 张显示「+1」
│   ☑  整理旅行照片  [🖼️]              │ ← 已完成，沉到 A 组底部
│                                      │
│ ▼ B 组：购物                          │
│   □  购买生日礼物（附参考图）    📄   │
│      [🖼️][🖼️][🖼️]                  │
│                                      │
│ [ + 输入新任务... ]        [↕ 自动排序]│
└──────────────────────────────────────┘
↑ 右上角：⚙️（设置）  ×（隐藏到托盘）
```

> **点击任意 [🖼️] → 弹出全屏预览窗口，底部显示图片索引（如 2/5）**
> **点击 📄 → 用系统默认程序打开关联的 md 文档；无文档时点击可新建/关联**
> **拖动任意任务可改变顺序；点击「自动排序」才按规则重排**

## 七、成功指标（V1.0）

- 用户能**在 10 秒内完成**：创建任务 → 粘贴/拖入 几 张图片 → 点击预览
- 图片添加体验流畅度对标 PixPin：截图软件复制后，`Ctrl+V` 一步入库
- 90% 用户认为「图片功能 + 排序分组直观易用」（通过可用性测试）
- 应用启动后内存占用 ≤ 80 MB（50 条任务、每条平均 2 张图）
- 窗口位置、尺寸、设置在重启后 100% 正确恢复
